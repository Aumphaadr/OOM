# Правки, упражнения и главы

Самый полезный вклад в ООМ — сообщение об ошибке: неверное число, упражнение,
которое не решается или решается само, инструмент, который ведёт себя не так,
неточная подпись. [Заведите issue](https://github.com/Aumphaadr/OOM/issues/new):
какая сцена или какое упражнение, что сделали, что увидели и что ожидали увидеть.

Правки принимаются на условиях лицензии проекта — [MIT](LICENSE).

## Как устроен проект

- `src/core/` — точное ядро: числа `Rational` на bigint, объекты и инструменты,
  журнал событий `Session` (единственный канал изменений, сквозной undo),
  цели-предикаты упражнений.
- `src/scenes/` — сцены-плагины: каждая рисует свои объекты на холсте и строит
  свою панель в сайдбаре.
- `src/ui/` — оболочка, читалка учебника, настройки.
- `src/icons/` — значки: копии из набора Klaarheid Icons и молоток ООМ.
- `public/textbook/` — учебник: `manifest.json` (порядок глав), главы HTML
  в `chapters/`, упражнения JSON в `exercises/`. Правится без пересборки.
- `docs/` — описания сцен и дизайн-решения.
- `tests/` — смоук-тесты (vitest): ядро, решаемость всего задачника, DOM, значки.

## Новое упражнение

1. Файл `public/textbook/exercises/<id>.json`: задание `task`, сцена `scene`,
   доска `board`, цель `goal`; по желанию — подсказки `hints`, лимит ходов
   `maxSteps`, чекпоинт `checkpoint` и обстрел границ `boundary`. Доску удобно
   собрать на самой доске и взять пунктом «Заготовка упражнения — в буфер»
   в меню доски.
2. Кнопка в главе: `<button class="ex-btn" data-exercise="<id>">Задание N. …</button>`.
3. Решатель в `SOLVERS` в `tests/exercises.test.ts` — обязателен: тест
   проверяет, что цель не выполнена сразу после загрузки, достигается
   решателем и укладывается в `maxSteps`. У каждого контрпримера с целью —
   решатель `<id>#c<номер варианта>`, у обстрела — `<id>#b`.
4. В чекпоинте ровно один верный вариант, у каждого неверного — диагноз
   `diagnosis`.
5. Строка в [CHANGELOG.md](CHANGELOG.md) в разделе «Не опубликовано».

Новая глава — файл в `public/textbook/chapters/` и строка в `manifest.json`;
тест загрузки приложения (`tests/app-boot.test.ts`) сверяет число глав —
его тоже поправить.

## Проверка перед публикацией

- `npm test` — все тесты зелёные.
- `npm run build` — типы сходятся, сборка собирается.
- Изменённые сцены и упражнения пройдены в браузере (`npm run dev`) на экране
  ноутбука, около 1366×768: панели и задание не закрывают объекты, в консоли
  браузера нет ошибок.

## Правила

- **Точная арифметика.** Модель хранит рациональные числа; float — только
  для отрисовки. Приближение всегда помечено знаком «≈».
- **Журнал событий — единственный канал изменений.** Сцены, история и цели
  подписываются на него, а не меняют модель в обход.
- **Честные отказы.** Невозможное — свойство инструмента («делить на ноль
  нельзя»), и отказ говорит словами, почему.
- **Урок — данные, не код.** Пресеты доски и упражнения — JSON.
- **Прибамбасы по запросу.** История, шлейфы значений, швы лент и настройки
  показываются, только когда их попросили.
- **Значки — только из набора.** Эмодзи и символы шрифта значками не служат:
  на каждом школьном компьютере они выглядят по-своему. В разметке значок
  ставится через `data-icon="имя"` или `icon('имя')`, на холсте — через
  `drawIcon`. Пиктограмма внутри текста (субтитр, задание, глава) — метка
  из таблицы `PICTOGRAMS` в `src/icons/index.ts`, её оболочка сама заменит
  значком. Тест `tests/icons.test.ts` не пропустит пиктограмму мимо таблицы.

## Чужие файлы

Всё, что не создано для проекта, — шрифт, картинка, звук, библиотека, набор
данных — добавляется, только если:

1. лицензия разрешает свободное использование, в том числе в образовательных
   организациях и коммерческих продуктах;
2. текст лицензии лежит рядом с файлом — для шрифта это `OFL.txt` в той же
   папке (и копия в `public/`, чтобы попасть в сборку);
3. в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) появилась строка: что это,
   откуда, кто автор, какая лицензия и где файл лежит.

Шрифты подключаются своими файлами из репозитория, не с чужих серверов.

Значки берутся из набора [Klaarheid Icons](https://aumphaadr.github.io/Klaarheid-Icons/)
(MIT-0) командой синхронизации:

```
npm run icons:sync -- <путь к Klaarheid-Icons> [имя …]
```

Она копирует значки из `svg/fill` набора байт в байт в `src/icons/klaarheid/`
(новые — по именам из командной строки, остальные — обновляет), пересобирает
список имён `src/icons/names.ts` и раздел «Значки» в THIRD-PARTY-NOTICES.md.
На значки набора действует только MIT-0. Если набор когда-нибудь снова заведёт
список значков под другими лицензиями (`src/third-party.mjs`), синхронизация
остановится, а не напишет в разделе неправду. Руками файлы значков и этот раздел
не правятся.

Тексты и задания — свои. Условия задач, таблицы и иллюстрации из учебников,
экзаменационных материалов ФИПИ и чужих сайтов не копируются. Сослаться на тип
экзаменационного задания можно, но условие и числа придумываются заново.

## Версии

Номер версии называет автор. Пока его нет, [CHANGELOG.md](CHANGELOG.md) ведётся
по датам публикации: всё, что ещё не выложено, собирается в разделе
«Не опубликовано».
