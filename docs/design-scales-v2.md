# Дизайн: весы v2 — неизвестное на обеих чашах

Сейчас весы решают только «раскопай x»: слева стопка наклеек над секретом,
справа число (docs/design-scales.md). Школьная реальность 6–7 класса —
уравнения вида **2x + 3 = x + 8**: x живёт на обеих чашах, и главный навык —
«перенос» — на самом деле не перенос, а честный удар по обеим чашам сразу.
Это вторая серия весов; первая остаётся как есть (у неё своя роль — LIFO
наклеек и обратные инструменты).

## 1. Модель: линейная чаша вместо стопки

Стопка наклеек v1 хранит ИСТОРИЮ операций (LIFO). Для x с обеих сторон
история не нужна — нужна ФОРМА. Ограничиваемся линейными уравнениями
(это весь диапазон ФРП 6–7 класса) и храним каждую чашу как пару
коэффициентов:

```ts
/** Линейная форма k·x + b (оба — Rational). */
interface LinForm { k: Rational; b: Rational }

interface EquationObject extends ObjectBase {
  kind: 'equation';
  name: string;            // имя неизвестного: x
  secret: Rational;        // истинное значение (проверка равновесия)
  left: LinForm;           // 2x + 3
  right: LinForm;          // 1x + 8
  solved: boolean;         // достигнута форма x = c
}
```

Ключевое решение: **никаких деревьев выражений**. Линейная пара (k, b)
покрывает весь материал, тривиально сериализуется, а форма чаши всегда
читается вслух: «2x + 3». Нелинейное (x², скобки с x) остаётся весам v1
и сцене «Площади» — не тащить всё в один объект.

## 2. Инструменты: старые молотки + два новых

Удар по уравнению = удар по ОБЕИМ чашам (транзакция, как scalesApply v1):

- **±N** (есть): b меняется у обеих чаш. «Перенос слагаемого» = «−3 по
  обеим чашам» — миф о «переносе с переменой знака» умирает на глазах.
- **×N, ÷N** (есть): k и b умножаются у обеих чаш. ÷0 не существует;
  **×0 — легальный удар с фейерверком**: уравнение сгорает в 0 = 0,
  «решено всё» — наглядный урок потери информации (рифма с ×0 конвейера).
- **±x** (НОВОЕ): op `addx` / `subx`, модификатор n = коэффициент:
  «−x» меняет k обеих чаш на −1. Подпись молотка: «−x», «+2x», «−½x».
  В PrimitiveOp эти операции не входят — они применимы ТОЛЬКО к уравнению
  (сигнатура: по числу/ленте молоток «−x» отказывает: «здесь нет x»).
  Это отдельный EquationOp, чтобы не раздувать makeTool и весь существующий
  код switch-ей.

Решение = форма «1·x + 0 = 0·x + c»: solved, коробка открывается, secret
показан. Проверка честности: secret обязан удовлетворять уравнению при
импорте (методист не может выдать противоречивую заготовку).

## 3. Сцена: чаши-выражения и наклон

- Каждая чаша рисует свою форму: слева «2x + 3» (коробка x ×2 + гирьки),
  справа «x + 8». Коробки x — те же запертые коробки, что в v1.
- **Равновесие всегда истинно** (обе чаши равны при подстановке секрета) —
  весы стоят ровно, пока уравнение уравнение. Спецэффекты:
  - ×0: обе чаши вспыхивают и пустеют (0 = 0), стрелка «решено» не даётся;
  - удар только по одной чаше НЕВОЗМОЖЕН в принципе (в v2 нет такого жеста)
    — «что сделал с одной, сделай с другой» зашито в физику, а не в правило.
- Субтитры: «−x: 2x + 3 = x + 8 → x + 3 = 8» — обе формы до/после.
- Undo: журнал хранит (left, right) до удара — обычная запись.

## 4. Цели и упражнения

Новый предикат в goal.ts:

```ts
| { kind: 'equation-solved' }               // достигнута форма x = c
| { kind: 'equation-form'; left: string; right: string }  // «x + 3 = 8» — промежуточная форма
```

`equation-form` позволяет вести за руку: «сначала убери x справа» (цель —
форма «x + 3 = 8»), потом «теперь гирьки» — лестница из двух-трёх упражнений
вместо одного большого прыжка.

## 5. Дистракторы (999) — они тут золотые

- **«Перенос меняет знак по волшебству»** — правильный вывод через удар:
  «−3 бьёт по обеим чашам; справа 8 − 3 = 5, слева 3 исчезло». Дистрактор:
  «при переносе через = число меняет знак само» — контрпример: ударь +3
  (не −3) и посмотри, что никакого «переноса» нет, есть два одинаковых удара.
- **«x нельзя вычитать — это же буква»** — контрпример: −x по 2x + 3 = x + 8
  честно даёт x + 3 = 8.
- **«Сократим x с обеих сторон» в 2x = x** — опасный случай: ÷x запрещён
  (нет такого молотка), а −x даёт x = 0. «Ноль — тоже ответ» — канон.
- **Опасные заготовки**: 2x + 3 = 2x + 5 (после −2x остаётся 3 = 5 — весы
  ломают равновесие?! Нет: такая заготовка невозможна по инварианту секрета —
  и это правильно; урок «нет решений» подаётся ЧЕРЕЗ отказ конструктора
  в лаборатории, отдельным текстом главы, а не живой доской. В MVP не делаем
  вид, что противоречивые уравнения — обычные жители весов).

## 6. Объём работ (оценка)

1. Ядро: EquationObject, LinForm-арифметика, equationApply (±N, ×N, ÷N, ±x),
   отказы, solved-детекция, сериализация, undo — компактно, всё по образцу
   scalesApply.
2. Цели equation-solved / equation-form.
3. Сцена: рендер чаш-выражений (наибольшая часть), спавн из панели весов
   (поля «левая: 2x+3», «правая: x+8», секрет).
4. Глава «Уравнения-2: x с обеих сторон» + 3 упражнения лестницей + чекпоинт
   «что такое перенос» + обстрел (2x = x → x = 0).
5. Тесты: LinForm-арифметика, транзакционность, ×0, решатели упражнений.

## 7. Не делаем (v2)

- Нелинейные выражения, скобки с x, x в знаменателе — не в этой серии.
- ÷x как молоток — принципиально: деление на x теряет корень x = 0,
  а сигнатура «делителя-ноль не существует» не может проверить x ≠ 0,
  пока x заперт. Честный запрет с репликой.
- Системы уравнений, два неизвестных — далеко за горизонтом.
- Автогенератор уравнений — после полевых испытаний основного сценария.
