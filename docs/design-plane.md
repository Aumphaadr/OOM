# Дизайн: сцена «Плоскость» (координатная плоскость)

Самая востребованная сцена по ревизии стенограмм: её ждут десять серий
(29, 30, 42, 49, 50, 51, 55, 56, 58, 59 линии v2 — от адресов точек до
интеграла). Строим ПОЭТАПНО: каждый этап — самостоятельная ценность,
никакой этап не требует переделки предыдущего.

## 0. Главная идея: график — это след инструмента

Никакой новой сущности «функция» в ядре НЕ появляется. У нас уже есть
инструменты (включая комбо с цепочками до 6 шагов) — а график по парадигме
ООМ и по стенограмме 30 — это «след машины». Значит:

**Сцена рисует СЛЕД ИНСТРУМЕНТА, ВЗЯТОГО В РУКУ.** Взял молоток «×2» —
увидел прямую через ноль. Взял комбо «×2 ∘ +3» — прямую с высотой старта 3.
Взял «x²» — чашу. Молоток и его портрет — одно и то же, буквально.

Это переиспользует всё: кузницу, комбо-конструктор, руку, hidden-режим
(след чёрного ящика можно прятать!), и не добавляет в модель ни одного типа.

## 1. Этап A — «Адреса» (серия 29): точки на плоскости

**Новый объект ядра** (последний член объединения):

```ts
interface PointObject extends ObjectBase {
  kind: 'point';
  label: string;      // Т1, Т2…
  x: Rational;        // адрес и есть данные — scenePos не используется
  y: Rational;
}
```

- Оси: две числовые прямые перпендикулярно, общая сетка-клетка (родство
  с «Площадями» видно глазами). Камера: пан за пустое место, зум колесом —
  как в «Прямой». Подписи целых на осях, начало координат выделено.
- Спавн: панель сцены (поля «x», «y») и двойной клик по плоскости
  (со снапом к целым; Shift — к половинкам). Точка подписана «(3; 2)».
- Перетаскивание точки — транзиент + коммит (как ползунок переменной);
  событие `point-moved {object, note}` в журнале, сквозной undo
  (PointState {x, y}).
- Выделение/рамка/Delete/Ctrl+C-V — грамматика коробок.
- Порядок пары — методическая суть серии 29: подпись всегда «(x; y)»,
  а при перетаскивании подсвечивается «маршрут»: пунктир вбок + вверх.
- **Цель**: `point-at {x, y}` — на доске есть точка с адресом.
  Упражнения: «посели точку в (3; 2)», «построй прямоугольник по четырём
  адресам» (4 цели-точки через values-подобный список: `points-at {list}`).

Объём: тип + сериализация + цели + сцена с камерой. Самая большая часть —
сцена, но она собирается из готовых кусков (камера прямой, грамматика
коробок, снап площадей).

## 2. Этап B — «Следы» (серии 30, 49, 50, 51): график инструмента

- Молоток в руке → его след на плоскости (полупрозрачная линия):
  для каждого пиксельного столбца x вычисляется tool.apply(x) — float
  ТОЛЬКО для отрисовки, модель остаётся точной. Отказы сигнатуры честны
  и на графике: след √x просто не существует левее нуля — дыра видна глазами.
- **Жест «прогони вход»**: клик молотком по оси X в точке a — точка (a; 0)
  поднимается/опускается к следу: (a; tool(a)), с ярлычком удара. Это
  и есть «пара вход-выход = адрес» из серии 29, сыгранная рукой.
- Несколько следов: панель сцены — чекбоксы «закрепить след» (до 3 цветов),
  чтобы сравнивать: ×2 против ×3, след и его отмотка.
- Чтение: подсветка точек пересечения закреплённых следов (серия 51 —
  «точка встречи»), прокол оси X (корни — 49), заливка «след выше/ниже оси»
  по галке (50 — неравенства взглядом).
- **Цель**: `point-on-trace` не нужна — хватает `point-at` (методист знает,
  куда должна приехать точка). Для систем: `point-at` в точке пересечения.
- Парабола — бесплатно: след молотка x². Дискриминант-счётчик проколов —
  это просто картинка следа квадратичного комбо. ВНИМАНИЕ: комбо вида
  «x², потом −4» строит y = x² − 4, а вот y = x² + 3x — НЕ цепочка
  примитивов от одного входа. Для MVP хватает форм «a·(x+b)² + c»
  (комбо «+b ∘ x² ∘ ×a ∘ +c») — все школьные параболы этим покрыты
  через выделение полного квадрата, и это даже методически честно.

## 3. Этап C — «Стрелки» (серия 42): векторы

- VectorObject {dx, dy} ИЛИ дешевле: вектор = инструмент «перенос» для
  точек? По серии 42 вектор — команда без места. MVP: стрелка-объект
  с хвостом где угодно (scenePos) и данными {dx; dy}; сложение — жест
  «прицепи хвост к носу», сумма рисуется пунктиром.
- Молотки ×k и ×(−1) по стрелке: растяжка и разворот (готовая семантика).
- Отложить можно без ущерба этапам A–B.

## 4. Этап D — «Старшие» (серии 55, 56, 58, 59): по одной фиче

- **Волна (55)**: требует инструмента-синуса. Вопрос отложен: sin(x) не
  Rational — конфликт с точным ядром. Вариант: отдельный «приближённый»
  инструмент с ≈-политикой (как корни: 3 знака). Решить при подходе.
- **Экспонента (56)**: инструмент qˣ — та же ≈-политика для дробных входов,
  на целых точен. Тоже отложено, дизайн-заметка есть.
- **Касательная-лупа (58)**: зум камеры УЖЕ даёт эффект «кривая выпрямляется»;
  добавить только «прилипающую» секущую по двум точкам следа.
- **Клетки под следом (59)**: заливка клеток между следом и осью на отрезке,
  счётчик клеток — прямое родство с «Площадями».

## 5. Изометрия (стереометрия, серия 57) — отдельная сцена, потом

Решение согласовано: НЕ WebGL, а изометрическая проекция на нашем Canvas 2D.
Кубоид = слои ромбов, послойное заполнение кубиками (счётчик слоёв —
«ленивый пересчёт» в 3D), сечения — подсветка среза. Вращения камеры нет —
фиксированный ракурс, как на клетчатой бумаге у чертёжников. Красивое
крутящееся 3D остаётся Blender-у (видеоряд стенограмм); участие пользователя
приветствуется именно там. Дизайн-док сцены — после «Плоскости».

## 6. Порядок реализации

1. Этап A целиком (тип, цели, сцена, глава «Адреса» + 2–3 упражнения).
2. Этап B: след руки + прогон входа + закрепление следов (глава «Следы»).
3. Чтение следов: проколы, заливки, пересечения (главы про корни/неравенства/системы).
4. Этапы C–D по одному, по мере надобности глав.

Не делаем в MVP: произвольные формулы текстом (только инструменты!),
полярные координаты, графики по точкам-таблицам, три и более осей.
