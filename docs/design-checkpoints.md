# Дизайн: чекпоинты с дистракторами (методика 999 в лаборатории)

Первоисточник — [стенограмма 999](../../idea/стенограммы/999.txt): опасные и
безопасные случаи, порядок заданий как диагностический инструмент. Перевод на
язык приложения — [webapp-concept.md §4–5](../../idea/webapp-concept.md):
ошибка ученика — это почти всегда **правильное применение неправильного
инструмента**, и наша задача — увидеть, какой ложный молоток он себе сковал.

Цикл лаборатории по 999: **эксперимент → чекпоинт-вывод → обстрел границ →
передача в тетрадь**. Упражнения (эксперимент) и главы (передача в тетрадь)
уже есть; этот дизайн добавляет два недостающих звена — чекпоинт и обстрел.

## 1. Что такое чекпоинт

После того как ученик выполнил упражнение-эксперимент (цель достигнута),
вместо простого «Готово!» появляется вопрос: **«Что ты заметил?»** — и варианты
формулировки вывода. Среди вариантов один честный и 2–3 дистрактора — реальные
ложные обобщения, которые дети приносят с уроков (999: «x² — это ×2»,
«x² — приписать ноль», «частное в числитель, остаток в целую часть»).

Ключевые решения:

- **Выбор дистрактора не карается, а проверяется.** Клик по ложному выводу
  загружает **контрпример**: мини-доску с объектом и инструментом, на которых
  ложное правило даёт другой ответ, чем настоящий молоток. Текст в духе 999:
  «Может показаться, что… Проверь: если x² — это ×2, сколько будет 7²?
  Ударь и посмотри». Ученик бьёт — вывод ломается у него на глазах,
  возвращаемся к вопросу (вариант помечен как «проверен и не подтвердился»).
- **Правильный вывод тоже не принимается на веру** — он ведёт в обстрел
  границ (§3). Вывод считается принятым только пережив обстрел.
- Никаких таймеров и очков (анти-фичи); порядок вариантов фиксирован
  методистом, не перемешивается — предъявление дистракторов тоже подчиняется
  правилу «опасное не раньше, чем закрепилось безопасное».

## 2. Данные: расширение ExerciseSpec

Чекпоинт — необязательный блок упражнения; появляется после выполнения цели.

```ts
/** Вариант вывода в чекпоинте. */
interface CheckpointOption {
  text: string;             // «возвести в квадрат — умножить число на само себя»
  correct?: boolean;        // ровно один вариант — true
  /** Диагноз для карты пробелов: каким ложным инструментом бьёт ученик. */
  diagnosis?: string;       // «подменяет x² на ×2»
  /** Контрпример: доска, на которой ложный вывод даёт расхождение. */
  counter?: {
    prompt: string;         // «Если x² — это ×2, то 7² = 14. Проверь ударом»
    board: BoardJson;       // фишка 7 + молоток x² (allowConstruct = false)
    goal?: GoalSpec;        // обычно any-object-value: дождаться удара
  };
}

interface CheckpointSpec {
  question: string;         // «Что ты заметил?»
  options: CheckpointOption[];
}

// В ExerciseSpec добавляется:
//   checkpoint?: CheckpointSpec;
//   boundary?: BoundarySpec;   // §3
```

Дистракторы пишет методист — это конечный, годами наблюдаемый список
(999: 7² = 14 ⇒ ×2; 7² = 70 ⇒ ×10; 13² = 109 ⇒ поразрядное возведение).
Таблица `{ответ → ложный инструмент}` из webapp-concept §5 живёт именно здесь.

## 3. Обстрел границ

Вывод, выбранный правильно, проверяется на **опасных объектах**: 0, 1,
отрицательные, числа между 0 и 1 — то, на чём ложные обобщения дают трещину,
а честное правило выживает.

```ts
interface BoundarySpec {
  prompt: string;           // «Вывод хорош. Переживёт ли он вот эти фишки?»
  board: BoardJson;         // те же инструменты + опасный набор: 0, 1, −3, 1/2
  goal: GoalSpec;           // например all-values или any-object-value
}
```

Механика проста и уже есть в ядре: загрузить доску, дать ученику бить тем же
молотком по пограничным объектам. Нейтральные удары (+0, ×1 не трясут),
отказы сигнатур (√ от −4) и «≈» у иррациональных — всё это уже работает и
именно здесь начинает приносить методическую пользу: границы темы ученик
щупает руками, а не читает сноской.

## 4. Поток в читалке (конечный автомат упражнения)

Сейчас: `active → done`. Станет:

```
experiment ──цель──► checkpoint ──верный──► boundary ──цель──► done
     ▲                   │ дистрактор                            
     │                   ▼                                       
     │               counter (мини-доска, удар)                  
     │                   │ увидел расхождение                    
     └───────────────────┴──► возврат к вопросу (вариант погашен)
```

- Панель «Задание» получает третье состояние: **карточка чекпоинта**
  (вопрос + кнопки-варианты на месте текста задания). Это та же task-panel,
  никакого нового UI-слоя.
- Контрпример и обстрел используют существующий механизм `importBoardData`
  (с `this.active = null` на время загрузки — защита от самовыполнения уже
  отработана) и `allowConstruct = false` — головоломка заперта.
- Кнопка «Начать заново» перезапускает всю цепочку с эксперимента.
- Если `checkpoint` не задан — поведение прежнее (все 32 упражнения живы).

## 5. Диагностика: журнал выводов

Каждый выбор дистрактора — запись с диагнозом (реализация: ui/diagnoses.ts;
в журнал Session не пишем — журнал обслуживает undo, а ответ на вопрос
не «отматывается»; след в истории оставляет обычная реплика say()):

```ts
{ when: string; exerciseId: string; diagnosis: string }
```

- Копится в localStorage (`oom-diagnoses-v1`).
- Преподавателю MVP показывает **карту диагнозов** — простой список в
  дропдауне истории: «x²: подменяет на ×10 (2 раза, гл. Степени)».
  Не отметка «3 из 7», а перечень ложных инструментов — готовый план лечения.
- Экспорт/импорт карты и привязка к сетке reports/class-NN — вторая волна
  (бэклог), формат события проектируем сразу с полем exerciseId, чтобы
  ничего не переделывать.

## 6. Правило безопасности последовательности

Из 999, кодифицируется как **правило методиста** (проверка — на моей стороне
при написании глав, автогенератора в MVP нет):

1. Первые 2–3 упражнения главы — безопасные случаи (никакие компоненты не
   совпадают, ложное правило дало бы неверный ответ, но тема ещё не даёт
   повода его сформировать).
2. Опасный случай — не раньше третьей позиции, и только после чекпоинта,
   где соответствующий дистрактор уже был предъявлен и сломан.
3. Домашние наборы (когда появится режим домашки) наследуют порядок:
   безопасные → опасные, без перемешивания.

Пример разметки опасности для «выделения целой части» (999): 19/6 безопасно
(3 и остаток 1 — не совпадают), 16/7 опасно (частное 2 = остаток 2),
15/5 опасно иначе (остаток 0 — «а куда девать ноль?»).

## 7. Пилотный контент: глава «Квадрат: что это на самом деле»

Обкатка на теме, для которой 999 даёт готовую диагностику:

1. **Эксперимент** (безопасно): фишки 7, 8, 9, 13 и молоток x². Цель — ударить
   по всем. Числа выбраны по 999: ни на одном ложные правила не совпадают
   с правдой.
2. **Чекпоинт**: «Что делает x²?»
   - «умножает число на само себя» ✅ → обстрел
   - «умножает число на 2» → контрпример: фишка 7 (ложь: 14, удар: 49),
     диагноз «подменяет x² на ×2»
   - «приписывает ноль справа» → контрпример: фишка 7 (ложь: 70, удар: 49),
     диагноз «подменяет x² на ×10»
   - «приписывает цифру 2 слева» → контрпример: фишка 13 (ложь: 213,
     удар: 169), диагноз «поразрядное возведение» (лютый случай из 999)
3. **Обстрел границ**: фишки 0, 1, −3, 1/2 и тот же x². Наблюдения: 0 и 1
   не сдвинулись (неподвижные точки), −3 стал положительным, 1/2 —
   уменьшилась! «Квадрат увеличивает число» — ещё одно ложное обобщение,
   ломающееся об 1/2 прямо в обстреле.
4. **Передача в тетрадь**: в тексте главы — 4 примера «теперь без молотков»,
   первые два безопасные, порядок 7², 8², 10², 13² — как в 999.

## 8. Не делаем (MVP)

- Автогенератор последовательностей с проверкой безопасности — правило
  пока живёт в голове методиста и в этом доке.
- Отдельный режим «Домашка» с код-ссылками — сначала чекпоинты в лаборатории.
- Свободный ввод формулировки вывода вместо выбора — распознавание текста
  размоет методику; выбор из тщательно составленных дистракторов честнее.
- Адаптивность («система сама решает, какой дистрактор показать») — порядок
  предъявления фиксирует методист.

## 9. Порядок реализации

1. Типы CheckpointSpec/BoundarySpec + конечный автомат в reader.ts,
   событие checkpoint-answered, копилка диагнозов в localStorage.
2. Карточка чекпоинта в task-panel (вопрос/варианты/статусы «сломан»).
3. Пилотная глава «Квадрат» (упражнение + 3 контрпримера + обстрел) —
   первый живой контент.
4. Карта диагнозов в дропдауне истории.
5. Смоук-тест: цепочка состояний, погашение дистракторов, запись диагнозов.
