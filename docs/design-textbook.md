# Дизайн: учебник и задачник с живыми сценами

Идея: текстовые уроки (учебник) + упражнения-сцены с заготовленной доской и целью
(«расковыряй уравнение», «разрежь ленту на трети», «угадай правило ящика»).
Референс формата — учебник Idyllium (манифест lessons.json + главы файлами + читалка).

## Почему это дёшево ложится на готовое

1. **Заготовленная доска уже есть** — это сериализация v1 (serialize.ts): упражнение
   хранит BoardJson, который препод собирает руками на доске и жмёт «сохранить как
   упражнение». Конструктор уроков из бэклога получается бесплатно.
2. **Цель — это предикат над сессией**, а вся модель меняется только через журнал
   событий. Проверщик цели — ещё один подписчик журнала, как субтитры:
   после каждого события проверяем предикат, выполнился — фанфары.
3. **Урок — уже данные** (LessonSpec); упражнение — расширение того же принципа.
4. **Критерии качества уже написаны**: для текстов — Т1–Т12/АТ1–АТ10 (конспект-урок,
   а не справочник), для заданий — К/А/Ц/Н + опасные/безопасные из 999
   ([../../task_design/](../../task_design/), [refs/pedagogy/](../../refs/pedagogy/)).

## Формат упражнения

```ts
interface ExerciseSpec {
  id: string;
  task: string;              // «Сними наклейки обратными молотками и открой коробку»
  scene: string;             // какая сцена открывается
  board: BoardJson;          // заготовленная доска (объекты + инструменты)
  goal: GoalSpec;            // декларативная цель
  hints?: string[];          // подсказки «в месте трения» (К9): называют инструмент, не решение
  maxSteps?: number;         // «уложись в N ударов» — челлендж оптимальности
}

type GoalSpec =
  | { kind: 'unknown-revealed' }                       // уравнение решено
  | { kind: 'any-object-value'; value: string }        // получить число N
  | { kind: 'all-values'; check: 'positive' | 'negative' | 'zero' }
  | { kind: 'tape-pieces'; pieces: string[] }          // лента порезана как надо: ['1/6','5/6']
  | { kind: 'tool-guessed'; toolId: string; answer: string }; // чёрный ящик: назвать правило
```

Проверщик целей живёт в ядре (goal.ts): чистая функция `checkGoal(session, goal)`,
вызывается подписчиком после каждого события. Никакой магии в сценах.

## Формат учебника

Как в Idyllium: `manifest.json` (разделы → главы) + главы в markdown/HTML.
Внутри главы — блоки упражнений по id: текст читается, упражнение открывается
на доске в один клик (режим «Учебник»: узкая колонка текста слева, сцена справа).
Тексты первых глав уже наполовину написаны — это стенограммы 001–004,
их конверсия в главы = редактура, а не сочинение с нуля.

## Драматургия упражнения (по 999 и Н-критериям)

Задачник главы — последовательность упражнений с фиксированным порядком:
разобранный пример (доска уже в процессе — досмотри и повтори) → безопасные →
предъявленный опасный случай → самостоятельные. «Уложись в N ходов» — необязательная
звёздочка. Каждый неправильный ход уже пишется в журнал — это сырьё для будущей
диагностики ложных инструментов (999): движок диагностики подключится к тем же данным.

## Этапы

1. **Плеер упражнений**: ExerciseSpec + goal.ts + панель «Задание» (текст, цель,
   галочка выполнения, подсказки по клику) + «сохранить текущую доску как упражнение»
   (JSON в буфер обмена). Учебника ещё нет — упражнения запускаются списком.
2. **Читалка**: manifest + главы + режим «Учебник» с колонкой текста.
3. **Контент**: глава «Отрицательные числа» (из OOM.txt и стенограммы 001) +
   задачник к ней; затем «Дроби» (002–004).

## Риски

- Главный труд — контент, не движок: главы писать по Т-критериям («урок», не
  «справочник»), задания — по чек-листу К/А. Движок — дни, контент — месяцы.
- Не растворить доску: свободная доска остаётся главным режимом занятия;
  учебник — материал для самостоятельной работы и домашки, не замена рук.
